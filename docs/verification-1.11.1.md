# 1.11.1 검증 기록

- 단위/STA 테스트: 233개 통과.
- 실제 WPF 창 통합 테스트: 개인 데이터와 분리한 테스트 DB로 통과.
- 100개 펼친 메모의 페이지 분할·다음 페이지·목록에서 열기, 논리적 표시 상태 저장, 입력·드래그 후 페이지 전환, 숨긴 메모 제외, 전체 접기/보임 및 페이지 재구성 확인.
- 전체 메모 새로고침, 휴지통 창 열기·재사용·닫기 확인. 휴지통 검색·선택·이벤트 연결은 STA 테스트로 확인.
- 패널 표시/숨김 상태에서 일괄 전환 중 포커스와 창 활성 상태 유지 확인.

## 성능

단일 모니터 작업 영역 1920×1032, 100% 배율. 렌더 대기 포함 값이며 저장은 별도로 측정했습니다.

| 시나리오 | 화면 반영 | 저장 |
|---|---:|---:|
| 타일 100개 정돈 | 36–125ms | 20–100ms |
| 20개 접기 | 51–114ms | 13–25ms |
| 20개 펼치기 | 145–178ms | 12–15ms |
| 100개 펼치기 및 페이지 분할 | 203ms | 24ms |

목표 시나리오인 타일 100개·펼친 메모 20개는 200ms 이내였습니다. 100개 펼치기는 200ms를 약간 초과했습니다. 이 수치는 현재 PC의 이번 실행 결과이며 다른 환경의 성능을 보장하지 않습니다.

## 검증 한계

- 페이지 재시작 복원은 저장 상태를 이용한 동일 프로세스의 재구성 경로로 검사했습니다.
- 물리 다중 모니터·배율 변경, 실제 한글 IME 조합, 모든 메뉴 버튼의 수동 클릭은 미검증입니다.
- 흰색 깜빡임 유무는 화면 캡처나 육안으로 확인하지 않았습니다.
- 통합 테스트 빌드에서 NuGet 취약성 피드를 일시적으로 읽지 못한 NU1900 경고가 있었습니다. 배포 게시 시 패키지 복원은 성공했습니다.

## 배포 실행 파일

런타임 포함 EXE 스모크 테스트 통과: 한글 문자열 저장, 36 DIP 타일, 재실행 후 접힘·본문 유지, 타일 펼치기, 창 숨김 후 프로세스 유지, 중복 실행 시 기존 목록 열기. 테스트 전역 단축키를 해제해 충돌을 방지하고 재실행 후 UIAutomation 창 참조를 다시 조회하도록 스크립트를 보정했습니다. 실제 IME 조합 테스트와는 구분합니다.
